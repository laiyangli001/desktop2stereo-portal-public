# 软件更新、APK 分发与授权试用实施方案 V2

## 1. 总体方案

登录成功后，每个 App 针对自身产品查询一次更新和权益。服务端负责授权裁决、版本策略和下载元数据，APK 全程由第三方分发。客户端读取本机版本号，决定是否展示更新，并按服务端裁决开放功能。

首版面向 Android 侧载，使用手动网盘下载和系统安装确认。国内、海外各按实测配置主备渠道。强制更新只用于必须停止兼容的旧版本，并要求可用的独立备用下载路径。业务服务器 APK 出口流量目标为零，第三方分发费用按实际账单计算。

## 2. 产品准入与权益

所有注册用户登录后都可查询并下载产品的已发布更新，包括未购买、试用中、试用到期和已付费用户。客户端使用稳定的 `product_code` 查询当前产品。服务端只校验账号会话和产品是否发布，下载资格独立于产品的使用权益。网站账号中心可列出全部已发布产品。

| 使用权益 | 客户端行为 |
|---|---|
| 已付费 | 该账号对该产品永久享有已购买功能。免费与收费切换时，功能、界面和入口保持一致，隐藏购买、试用和切换提示 |
| 公测或免费期间的未付费用户 | 按当前模式开放功能，隐藏付费入口 |
| 收费期间的试用用户 | 开放试用范围内的功能，显示剩余时间 |
| 收费期间的未购买或试用到期用户 | 开放基础功能，提供购买入口。更新查询、下载和安装均可用 |

每个账号与产品的永久授权独立保存。服务端实时裁决受保护操作，客户端按返回的权益状态展示。已付费界面以 licensed 为准，产品模式切换本身不触发弹窗、重新登录或更新提示。

## 3. 公测与个人试用

服务器用 UTC 时间和半开区间判定。公测在 `now >= beta_end_at` 时结束，试用在 `now >= trial_expires_at` 时失效。

| 情形 | 规则 |
|---|---|
| 公测期间 | 用户首次成功获得公测权益时记录 `first_beta_access_at`。公测期间可修改结束时间及 `post_beta_plan` |
| 公测转正式 | 公测参与者统一以最终 `beta_end_at` 起算。用户晚登录时仍按此时间计算，可能首次回来就已到期 |
| 正式期首次使用 | 公测未参与者在首次使用收费功能并成功领取试用时起算。网站登录、查更新、下载和免费期间使用均不触发 |
| 已付费 | 三种运营模式均优先返回 `licensed`，`expires_at = null`，客户端保持同一体验 |
| 关闭试用 | 停止发放新试用，已有个人试用保留原到期时间 |
| 收费 → 免费 | 未付费用户获得免费权限，隐藏试用和支付入口。保留原有试用记录 |
| 免费 → 收费 | 已付费用户继续使用。未付费用户按原试用记录判断，尚未领取的合资格用户可首次领取。运营可随时重复切换 |

首版试用按原到期时间连续计时，免费期间经过的时间照常计入既有试用窗口，恢复收费沿用原记录。首次进入收费功能的显式请求负责给合资格新用户发放试用。

公测结束时根据已生效的产品配置推导有效阶段，查询路径无需批量写入用户。公测参与者首次进入正式期时，或其他合资格用户显式领取试用时，按 `(user_id, product_id)` 唯一约束原子插入试用记录，冲突时读回既有记录。参与时间和生效阶段在同一事务中裁决，读取服务端时间一次。运营改期请求使用配置版本做并发控制，事务内确认仍处于公测期。

公测截止时的去向和试用参数以生效配置为准。保存阶段生效时间和参数快照，防止后续改配置或用户晚登录改变公测用户的试用窗口。正式期新用户按发放时策略生成个人记录。免费与收费切换只写产品模式及审计记录，付费和试用表保持原记录。提前转正式等价于发布一个新的截止时间。公测生效后锁定该次截止时间，个别延期走有审计的客服补偿。

## 4. 版本发布和渠道

| 对象 | 最小字段和约束 |
|---|---|
| `product` | 唯一 `product_code`、Android 包名、签名证书指纹、发布状态、阶段及收费模式配置及配置版本 |
| `product_membership` | 唯一 `(user_id, product_id)`、`first_beta_access_at`。仅记录公测参与事实 |
| `product_trial` | 唯一 `(user_id, product_id)`、起止时间、起算依据、策略版本 |
| `user_license` | 唯一 `(user_id, product_id)`，记录一次付费产生的永久授权及订单来源。以支付成功事件幂等发放。迁移按已支付订单补齐永久权益，保留原试用记录 |
| `product_release` | 唯一 `(product_id, version_code)`、展示版本、包名、证书指纹、SHA-256、大小、说明、发布状态 |
| `release_download_channel` | 所属版本、方式、服务商、适用地区、优先级、URL、提取码、启用状态和最近验证结果 |
| `product_update_policy` | 产品最低支持版本、配置版本、配置变更审计。首版可并入产品表 |

构建端生成已签名 APK 和发布清单，提取包名、版本号、文件大小和 SHA-256，用 `apksigner verify --print-certs` 核验签名。后台接收小体积清单和第三方地址。发布前在目标设备完成一次真实下载、哈希核对与覆盖安装，确认包名和签名证书兼容。首版使用通用 APK，若后续按 ABI 发布，再引入产物变体。  
来源：[Android 覆盖更新规则](https://developer.android.com/google/play/app-updates) · [apksigner](https://developer.android.com/tools/apksigner)

同一版本的各渠道应提供字节相同的 APK。链接故障只影响对应渠道。后台探测能确认页面可访问，真实下载能力仍要用目标地区、设备和预期账号条件验证。下发仍可用的主备渠道，后台告警并允许切换渠道。APK 固定发布后保持版本号与文件哈希绑定。撤回有缺陷的版本时，对已安装用户发布更高版本号的修复包。

国内沿用已有网盘，海外可以验证 GitHub Releases 或 Google Drive，按受众和下载实测选主备。对象存储或 CDN 作为应急直链，启用前确认预算。链接和提取码支持被转发，业务准入按注册账号统一判断。若后续使用第三方短期签名地址，签发条件同样覆盖所有注册用户。后台和日志应保护提取码，下载 URL 仅允许 HTTPS 和经验证的服务商域名。

## 5. 登录检查与强制更新

`POST /api/v1/products/{product_code}/bootstrap` 使用帐号会话鉴权。每次成功登录触发一次，网络失败时提供显式重试入口。账号会话有效且产品已发布时，服务端返回独立的权益与更新数据。无发布版本时，最新版本号与发布信息均返回 null，客户端先处理此分支。接口使用 `Cache-Control: no-store`。

```json
{
  "server_time": "2026-11-20T06:00:00Z",
  "product_code": "app_a",
  "entitlement": {
    "phase": "formal",
    "status": "trial",
    "expires_at": "2026-11-27T06:00:00Z",
    "remaining_days": 7
  },
  "update": {
    "latest_version_code": 2100,
    "min_supported_version_code": 2000,
    "release": {
      "version_name": "2.1.0",
      "file_size": 1073741824,
      "sha256": "<64 位十六进制字符串>",
      "release_notes": "修复播放中断",
      "downloads": [
        {
          "method": "manual_netdisk",
          "provider": "example",
          "url": "https://downloads.example.com/share/example",
          "extract_code": "abcd"
        }
      ]
    }
  }
}
```

| 客户端条件 | 行为 |
|---|---|
| 本地版本 ≥ 最新发布版本 | 静默，继续处理权益状态 |
| 最低支持版本 ≤ 本地版本 < 最新发布版本 | 普通更新提示，可稍后处理 |
| 本地版本 < 最低支持版本且存在可用升级包 | 展示强更页，保留退出、打开备用渠道和联系客服 |
| 低于门槛且全部渠道失效 | 进入明确的恢复页。兼容功能可继续，必须停用的服务端能力保持受限，提供重试与客服入口 |
| 无可发布版本 | `release = null`，客户端按权益和最低版本策略展示相应状态 |
| 更新检查超时 | 显示重试入口。有效权益缓存仍可按既定有效期使用，缺少有效权益时开放基础功能 |

最新发布版本与最低支持版本独立。后台提高最低版本前，必须确认目标版本和备用渠道可安装，并校验最低版本 ≤ 最新发布版本。正式发布坏包后，运营可撤回发布并重新评估最低版本门槛。兼容性降级可由后台降低门槛，明确必须禁用的能力由服务端继续执行业务限制。客户端版本号来自本机安装信息，统计上报可后置。旧版本受限期间，登录、更新检查和下载入口始终可访问。

客户端提供打开下载页、复制链接和提取码、切换备用渠道、安装指引。网盘或浏览器发起安装时，安装来源授权由 Android 按实际发起方管理。仅在本 App 自己发起安装的实现中处理 `REQUEST_INSTALL_PACKAGES` 等系统流程。浏览器或系统出现安全警告时，引导用户核对分发来源和包哈希。可选用系统文件选择器读取 APK 并校验 SHA-256。安装后重启读取本机新版本，下次登录自然完成版本比对。  
来源：[Android 安装来源权限](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls())

## 6. 在线授权、离线授权与安全

- 首版以在线登录裁决和服务端资源鉴权为主。用户登录期间，受保护业务接口仍按服务端当前时间和权益执行，更新检查维持登录一次。收到权益变更或拒绝访问时刷新对应 UI。
- 确有离线需求时，再引入标准签名权益凭证，绑定账号、产品、签发和到期时间，支持 `kid` 和公钥轮换。签名验证保护凭证完整性，离线到期与撤销时效取决于缓存有效期和设备时间可信度。凭证过期或时间异常时降级到基础功能，重新联网恢复。仅本地运行的功能应把客户端篡改风险计入商业设计。
- 有服务端依赖的功能优先在已有业务接口裁决权限。跨服务调用确有需要时再发短期、限定范围的令牌。APK 签名密钥与权益签名密钥独立管理。下载链接、提取码及会话令牌避免进入日志。试用首版通过账号与产品唯一约束防止重复发放，设备标识仅在有明确风控需求时引入。

## 7. 交付顺序和验收

| 阶段 | 交付与验收 |
|---|---|
| 1. 后端与后台 | 产品准入、发布清单、主备渠道、权益裁决、配置审计。验证多产品永久权益隔离、全部注册用户可查询和下载、试用到期用户可购买 |
| 2. Android 联调 | 登录查一次、读取本机版本、普通提示、下载和安装闭环。验证同版本静默、新于服务端静默、目标设备覆盖安装后数据保留。若面向头显，在实际设备上走通下载和安装 |
| 3. 公测试用上线 | 验证截止前后、延期、截止后晚登录、新用户首次进入、试用关闭、永久付费优先、并发领取只创建一条试用记录、反复切换免费与收费时已付费用户权益和界面一致、全部注册用户仍可更新 |
| 4. 强更上线 | 演练主源失效、全部源失效、撤回坏包、最低版本调整和高版本修复。验证退出和恢复路径，以及业务服务器全程无 APK 文件流量 |

上线后观察检查成功率、各下载渠道点击及故障情况。点击只代表打开下载页，安装成功可在下次登录时由本机版本变化统计。差分包、ABI 拆分和 P2P 待实际下载失败率、包体分布和流量成本说明有收益后再评估。
