# GitHub Release 在线升级

在线升级从 GitHub Release 读取源码归档，不需要单独生成或上传签名升级附件。Release 标签用于定位提交；下载内容的完整性由 SHA-256 暂存记录、GitHub HTTPS 和候选目录发布清单共同校验。

## 仓库配置

后台“系统升级”页可输入 GitHub 仓库地址，支持 `owner/repository` 和 GitHub 仓库 URL。默认仓库是 `laiyangli001/desktop2stereo-portal-public`。公开仓库不需要令牌；私有仓库可通过服务器环境变量 `D2S_GITHUB_TOKEN` 提供只读访问凭据。令牌只发送给 `api.github.com`，不会写入数据库或日志。

可选环境变量：

- `D2S_UPDATE_GITHUB_REPOSITORY`：默认仓库；
- `D2S_GITHUB_TOKEN`：私有仓库的只读令牌；
- `D2S_UPDATE_STAGING_DIR`：私有源码归档暂存目录，必须位于 `public/` 外；
- `D2S_UPDATE_CANDIDATE_DIR`：候选版本根目录，必须位于 `public/` 外；默认 `storage/updates/candidates`；
- `D2S_CA_BUNDLE`：可选受信 CA 文件。

## 发布与检测

将代码推送到 GitHub，在该提交创建正式 Release 并发布标签即可。GitHub 自动生成源码归档；发布时不需要额外生成网站专用签名包、签名清单或私钥。

后台检查更新时会：

1. 读取仓库最新正式 Release；
2. 根据 Release 标签查询对应完整提交 SHA；
3. 比较当前部署版本与 Release 提交；
4. 下载 GitHub 为该提交生成的源码归档。

页面显示 Release 标签、提交和检查结果。点击下载后，后端会重新检查所选 Release，避免检查后发布内容被替换。

## 源码校验与候选准备

源码归档最多 128 MiB，解压数据最多 512 MiB。后端会校验 GZip 格式、归档校验和、统一的顶层目录、文件类型、路径安全和重复文件；拒绝符号链接、硬链接、扩展头、绝对路径、反斜杠及路径穿越。只提取网站运行文件和 Composer 清单，不把测试、文档等仓库内容放进部署候选目录。

准备候选版本时还会：

- 要求候选 `composer.lock` 与当前版本一致，并复用当前 `vendor/`；依赖锁文件变化时停止，避免在服务器执行 Composer；
- 为实际运行文件生成发布清单并重新校验；
- 检查迁移文件清单及 SHA-256；
- 使用 PHP tokenizer 进行语法检查，不执行归档中的代码；
- 将完成的候选版本保存在 `public/` 外，并记录归档 SHA-256。

GitHub 源码归档的 SHA-256 是下载完整性记录，不是发布者签名。任何有权发布该仓库 Release 的人都能影响更新内容，因此仓库发布权限应由可信维护者控制。

## 当前安装边界

后台目前提供 Release 检查、源码下载和候选准备；这些步骤不会替换正在运行的网站，也不会执行数据库迁移或重启 PHP 服务。现有安装器是显式 CLI 流程，需要部署目录、已验证的数据库与商品图片备份集、迁移执行账户及健康检查地址。

因此，网页中展示“候选已准备”不代表“网站已升级”。要实现后台一键安装并展示安装、迁移、重启、健康检查进度，还需要在服务器配置受限的升级执行器，并将它接入部署目录与 PHP-FPM 服务；Web PHP-FPM 进程本身不应获得 root 或服务管理权限。生产服务器部署和重启尚未执行。
